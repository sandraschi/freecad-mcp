# freecad-mcp — MCP Server Capabilities

FreeCAD MCP exposes FreeCAD 3D modeling, BIM/architecture design, CFD fluid simulation (OpenFOAM CPU + FluidX3D GPU), and 3D printing workflows through 38 MCP tools. The server runs FreeCAD as a headless geometry engine via TCP bridge or subprocess, generates OpenFOAM case directories for Docker-based execution, and compiles FluidX3D GPU binaries via OpenCL.

## Architecture

The server operates in three modes: stdio (Claude Desktop), HTTP/SSE (Cursor, any MCP client), or dual transport. FreeCAD geometry operations go through a TCP bridge (FreeCAD.exe with fc_bridge.py on port 10946) with subprocess fallback (FreeCADCmd.exe). CFD tools generate OpenFOAM dictionary files at `work_dir/cfd_cases/` and execute solvers via Docker (openfoam/openfoam10-paraview56). FluidX3D GPU tools generate C++ setup files + config.json at `work_dir/fluidx3d_cases/` and compile/run via g++/MSVC + OpenCL. The web dashboard runs on port 10945. REST API and MCP SSE transport share port 10944.

## Tools by Domain

### Mechanical CAD (7 tools)

**freecad_status**: Check FreeCAD executable availability and version. No parameters. Returns: freecad_ok (bool), version (str, e.g. "FreeCAD 1.1.1 ..."), bridge_mode (str: "tcp" when FreeCAD GUI is running with the TCP bridge, "subprocess" when falling back to headless FreeCADCmd, "none" when FreeCAD is not found), work_dir (str). Call this first before any CAD operation to determine which execution mode is available.

**step_to_stl**: Convert STEP or STP assembly file to STL mesh for 3D printing, visualization, or further analysis. Parameters: file_name (str, required — STEP file in the uploads directory), output_name (str, default "output.stl"). Uses TCP bridge for AP214 assemblies which preserves all objects and their properties. Falls back to FreeCADCmd subprocess for simple STEP files. Returns: success (bool), output (str — the STL filename), data.objecsv (int — number of solid objects converted), data.size_kb (float — output file size).

**model_info**: Read CAD file metadata without converting the file itself. Works on STEP assemblies (returns object count per solid) and STL meshes (returns vertex/facet count). Parameters: file_name (str, required — STEP or STL filename in the uploads directory). Returns: success (bool), data.objecsv (list of objects with name, solids, volume, bounding box for STEP) or data.vertices/data.facets (for STL).

**create_shape**: Create geometric primitive (box, cylinder, sphere, cone) and export as STL mesh. All dimensions in millimetres. Parameters: shape_type (str: "box", "cylinder", "sphere", "cone"), params (dict — box: width/height/depth, cylinder: radius/height, sphere: radius, cone: radius/height), output_name (str, default "shape.stl"). Returns: success (bool), output (str — STL filename), data.size_kb (float).

**slicer_status**: Check PrusaSlicer availability and version. No parameters. Returns: available (bool), version (str), profiles_dir (str — path to PrusaSlicer profiles).

**slice_stl**: Slice an STL file to G-code for 3D printing. Parameters: file_name (str, required — STL filename in uploads), printer_profile (str, default "Prusa MK4"), filament_profile (str, default "PLA"), quality (str, default "0.20mm SPEED"), output_name (str, optional — auto-generated if omitted). Returns: success (bool), output (str — G-code filename), data.size_kb (float), data.path (str).

**freecad_gui**: Launch the FreeCAD desktop GUI application as a separate process. Parameters: file_name (str, optional — STEP/STL/FCStd file to open on launch). Returns: success (bool), message (str), process_pid (int). The process runs independently of the MCP server.

### BIM / Architecture (9 tools)

**bim_status**: Check FreeCAD Arch workbench and IFC module availability. No parameters. Returns: success (bool), bim_available (bool), bridge_mode (str), workbench (str, always "Arch (BIM)").

**bim_create_wall**: Create a parametric architectural wall as a BIM object with material, thickness, and height attributes. The wall is created via Arch.makeWall() from a Draft line segment. Parameters: length_mm (float, default 5000.0, minimum 1 — wall length), width_mm (float, default 200.0, minimum 10 — wall thickness), height_mm (float, default 2800.0, minimum 10), placement_x/y/z (float, default 0 — position in millimetres), rotation_z (float, default 0 — rotation around Z axis in degrees), output_name (str, default "wall.fcstd"). Returns: success (bool), output (str — FCStd filename), data.label (str), data.length/width/height (float), data.path (str).

**bim_create_slab**: Create a floor slab as a structural BIM element. Uses Arch.makeStructure() from a Part box. Parameters: width_mm (float, default 6000.0, minimum 100), length_mm (float, default 8000.0, minimum 100), thickness_mm (float, default 200.0, minimum 20), placement_x/y/z (float, default 0), output_name (str, default "slab.fcstd"). Returns slab properties.

**bim_create_column**: Create a structural column with selectable profile type. Supports rectangular, circular, and H-section profiles via Arch.makeStructure(). Parameters: profile_type (str: "rectangular"/"circular"/"h_section", default "rectangular"), width_mm (float, default 300.0, minimum 10 — X dimension or diameter for circular), depth_mm (float, default 300.0, minimum 10 — Y dimension), height_mm (float, default 3000.0, minimum 10), placement_x/y/z (float, default 0), output_name (str, default "column.fcstd"). Returns column properties.

**bim_create_window**: Create a window BIM object that auto-cuts its opening in a hosting wall. The wall is created automatically to host the window. Parameters: window_type (str: "fixed"/"casement"/"sliding"/"awning", default "fixed"), width_mm (float, default 1000.0, minimum 200), height_mm (float, default 1200.0, minimum 200), sill_height_mm (float, default 900.0 — height from floor), placement_x/y/z (float, default 0), rotation_z (float, default 0), output_name (str, default "window.fcstd"). Returns window properties.

**bim_create_door**: Create a door BIM object that auto-cuts its opening in a hosting wall. Parameters: door_type (str: "simple"/"glass"/"sliding_glass", default "simple"), width_mm (float, default 900.0, minimum 400), height_mm (float, default 2100.0, minimum 1500), placement_x/y/z (float, default 0), rotation_z (float, default 0), output_name (str, default "door.fcstd"). Returns door properties.

**bim_create_roof**: Create a sloped or flat roof via Arch.makeRoof() from a rectangular face. Parameters: width_mm (float, default 8000.0, minimum 100 — span direction), length_mm (float, default 10000.0, minimum 100 — ridge direction), angle_deg (float, default 30.0, range 0-75 — pitch, 0=flat), thickness_mm (float, default 100.0, minimum 10), placement_x/y/z (float, default 0, Z default 2800), output_name (str, default "roof.fcstd"). Returns roof properties.

**bim_export_ifc**: Export a FreeCAD .fcstd document to IFC (Industry Foundation Classes) format, the open standard for BIM data exchange. The source file must be in the uploads or outputs directory. Parameters: file_name (str, required — source .fcstd filename), output_name (str, default "building.ifc"). Returns: success (bool), output (str — .ifc filename), data.path (str), data.size_kb (float), data.objects (int).

**bim_import_ifc**: Import an IFC file from architects or structural engineers and convert to a FreeCAD .fcstd document with parametric BIM objects. Parameters: file_name (str, required — source .ifc filename in uploads), output_name (str, optional — auto-generated from source name). Returns: success, output, data.path, data.objects (int), data.object_names (list of strings).

### CFD / OpenFOAM (10 tools)

**cfd_status**: Check if Docker is available and the OpenFOAM Docker image is present. No parameters. Returns: docker_available (bool), docker_exe (str — "docker" or "podman"), openfoam_image (bool — whether openfoam/openfoam10-paraview56 is pulled), bridge_mode (str), cfd_case_dir (str — path to case storage directory).

**cfd_create_domain**: Create a parametric fluid domain geometry in FreeCAD and generate an OpenFOAM case skeleton with blockMeshDict. The geometry is exported as STEP and STL files. Domain types: channel (3D rectangular duct with inlet/outlet/walls), pipe (cylindrical tube with circular cross-section), box (all sides closed for cavity flow), nozzle (convergent-divergent), custom (import existing STEP geometry). Parameters: domain_type (str, default "channel"), length_m (float, default 1.0, minimum 0.01 — domain length in metres), width_m (float, default 0.1, minimum 0.001), height_m (float, default 0.05, minimum 0.001), inlet_radius_m (float, default 0.02 — for pipe/nozzle), outlet_radius_m (float, default 0.01 — for nozzle), mesh_cells (int, default 20000, minimum 100 — target cell count), case_name (str, default "channel_flow" — directory name), step_file (str, optional — existing STEP for custom type). Returns: success (bool), case_name (str), case_dir (str), data.domain_type (str), data.dimensions_m (list of 3 floats), data.mesh_cells (int), data.step_file (str).

**cfd_configure_physics**: Generate all OpenFOAM physics and solver configuration dictionaries. Creates controlDict (time control, function objects for force monitoring), fvSchemes (spatial discretisation schemes: Gauss linear, upwind), fvSolution (linear solvers: GAMG for pressure, smoothSolver for velocity, relaxation factors), transportProperties (Newtonian viscosity model), turbulenceProperties (RAS model selection). Parameters: case_name (str, required), solver (str: "simpleFoam"/"pisoFoam"/"pimpleFoam", default "simpleFoam"), flow_type (str: "laminar"/"kEpsilon"/"kOmegaSST", default "laminar"), fluid_nu (float, default 1e-6 — kinematic viscosity in m2/s), fluid_density (float, default 1000 — kg/m3), inlet_velocity (float, default 1.0 — m/s), end_time (float, default 1000 — iterations for steady), delta_t (float, default 1.0 — time step), write_interval (int, default 100). Returns: success, case_name, data.solver, data.flow_type, data.Re_estimate (float), data.nu, data.density, data.inlet_velocity.

**cfd_set_boundary**: Configure boundary conditions for a specific patch and field. Generates the actual field file (e.g. 0/U, 0/p) in the OpenFOAM case directory. Supported BC types: fixedValue (Dirichlet), zeroGradient (Neumann), inletOutlet (zero gradient outflow, fixed value backflow), noSlip (zero velocity wall), slip (free-slip wall), symmetry, empty (2D), wedge (axisymmetric), cyclic, pressureInletVelocity, pressureInletOutletVelocity, totalPressure, flowRateInletVelocity. Parameters: case_name (str, required), patch_name (str: "inlet"/"outlet"/"walls"), field_name (str: "U"/"p"/"k"/"omega"/"nut"/"alphat"), bc_type (str, default "fixedValue"), value (str, default "uniform (0 0 0)" — OpenFOAM value syntax). Returns: success, case_name, data.patch/field/bc_type/file.

**cfd_build_case**: Validate that a complete OpenFOAM case directory is ready for execution. Checks for all required files: blockMeshDict, controlDict, fvSchemes, fvSolution, transportProperties, turbulenceProperties, initial field files (U, p, plus k/omega/nut for turbulent cases). Parameters: case_name (str, required). Returns: success, case_name, data.files (list of present files), data.missing (list of missing files), data.ready (bool — true when no files missing).

**cfd_run_solver**: Execute OpenFOAM solver steps inside a Docker container. The case directory is mounted at /case inside the openfoam/openfoam10-paraview56 container. Steps: blockMesh (generate hexahedral mesh from blockMeshDict), checkMesh (validate mesh quality — skewness, aspect ratio, non-orthogonality), simpleFoam/pisoFoam/pimpleFoam (execute the solver), decomposePar (decompose for parallel), reconstructPar (reconstruct parallel results), postProcess (run function objects like forces). Parameters: case_name (str, required), steps (str, default "blockMesh,checkMesh,simpleFoam" — comma-separated), parallel (bool, default false), n_cores (int, default 4, range 1-64). Returns: success, case_name, data.steps_completed (list), data.log (str), data.exit_codes (dict).

**cfd_read_results**: Parse simulation results from a completed OpenFOAM case. Reads time directories (numeric folders), force coefficients from postProcessing/forces/ (pressure forces on specified patches), and solver residuals from the solver log file. Parameters: case_name (str, required). Returns: success, case_name, data.times (list of time directory names), data.latest_time (str), data.forces (dict — per-time force coefficients), data.final_residuals (dict — last residual per solved field like p, Ux, Uy, Uz), data.converged (bool — true when all residuals below 1e-4).

**cfd_parametric_study**: Run a parameter sweep by duplicating a base case across multiple parameter values. Each variant inherits the base case configuration. Useful for design optimization, sensitivity analysis, and generating training data for ML surrogate models. Parameters: case_name (str, required — base case name, suffixed _0, _1, etc.), parameter (str: "inlet_velocity"/"length"/"width"/"height"/"fluid_nu"/"angle"), values (str — JSON array like "[0.5, 1.0, 2.0]"), run (bool, default false — execute each case if true). Returns: success, base_case (str), data.parameter (str), data.cases (list of variant dicts).

**cfd_nl2foam**: Convert a natural language fluid dynamics description into an executable OpenFOAM case configuration using an LLM. Supports Ollama and any OpenAI-compatible API endpoint. The LLM receives a system prompt about OpenFOAM configuration structure and returns a JSON object with solver selection, flow type, fluid properties, domain dimensions, mesh resolution, boundary conditions, and control settings. Parameters: description (str, required — natural language problem description like "Laminar pipe flow, Re=500, D=0.1m, water"), case_name (str, default "nl2foam_case"), model (str, default "gemma3:1b" — LLM model), api_url (str, optional — OpenAI-compatible endpoint like "https://api.openai.com"), api_key (str, optional). Returns: success, case_name, data.solver/flow_type/mesh/bc/reasoning/raw_response.

**cfd_sample_for_pinns**: Sample coordinate point clouds from CFD domain geometry for Physics-Informed Neural Network (PINN) training. Uses FreeCAD to sample boundary points (for BC enforcement in the loss function) and interior collocation points (for PDE residual evaluation). Compatible with NVIDIA Modulus, DeepXDE, PyTorch Geometric. Parameters: case_name (str, required), n_boundary (int, default 5000, minimum 100), n_interior (int, default 10000, minimum 100), output_format (str: "csv"/"json"/"numpy", default "csv"). Returns: success, case_name, data.n_boundary (int), data.n_interior (int), data.bbox (dict), data.output_file (str), data.format (str).

### FluidX3D GPU CFD (7 tools)

**cfd_fluidx3d_status**: Check if FluidX3D is cloned locally and a C++ compiler is available for building GPU simulations. FluidX3D is a lattice-Boltzmann GPU solver that runs on all GPU vendors via OpenCL (NVIDIA, AMD, Intel Arc, Apple Silicon). No parameters. Returns: fluidx3d_path (str or null — path to FluidX3D clone), compiler (str or null — detected compiler like "g++" or "cl"), ready (bool — true when both are available).

**cfd_fluidx3d_setup**: Generate a FluidX3D C++ setup file and a config.json for the pre-compiled runner. The setup.cpp is written to the case directory and can be compiled against the FluidX3D source tree. The config.json is read at runtime by the FluidX3D runner binary, eliminating the need for per-case compilation. Domain types: channel (rectangular duct), pipe (cylindrical tube), box (closed cavity), stl (custom geometry from STL file). Also supports: non-Newtonian viscosity (power-law Ostwald model), free-surface LBM (liquid-gas), thermal LBM (Boussinesq buoyancy), 2D mode, symmetry planes, parabolic/blasius inlet profiles, and multi-object STL configurations. LBM unit conversion computes lbm_velocity and lbm_nu from SI inputs to ensure stability (u <= 0.1, nu in 0.001-0.2 range). STL geometry is auto-discovered from multiple sources in priority: explicit stl_file → OpenFOAM of_case_name → matching case_name in cfd_cases/ → fluidx3d_cases/. Parameters: case_name (str, default "f3d_channel"), domain_type (str: "channel"/"pipe"/"box"/"stl", default "channel"), resolution_x/y/z (int, default 512/128/128), length_m (float, default 1.0), velocity_ms (float, default 0.01), viscosity_m2s (float, default 1e-6), density_kgm3 (float, default 1000), time_steps (int, default 50000), write_interval (int, default 1000), stl_file (str, optional), of_case_name (str, optional), plus advanced params: profile_shape, symmetry_axis, non_newtonian, free_surface, thermal, outlet_type, mode_2d, stl_configs_json. Returns: success, case_name, data.setup_file, data.resolution, data.cells (int), data.Re_estimate (float), data.lbm_nu, data.lbm_velocity, data.defines (list of enabled extensions).

**cfd_fluidx3d_compile**: Compile the generated setup.cpp against the FluidX3D source tree using the detected C++ compiler. Copies setup.cpp and defines.hpp into the FluidX3D src/ directory, then invokes g++ (with -std=c++17 -O3 -lOpenCL) or MSVC (with /EHsc /O2 /std:c++17 OpenCL.lib). Parameters: case_name (str, required), opencl_lib (str, optional — OpenCL library path hint, auto-detected if empty). Returns: success, case_name, data.binary (str — path to compiled binary), data.compiler (str), data.compile_time_s (float), data.warnings (str).

**cfd_fluidx3d_run**: Execute a compiled FluidX3D simulation on the GPU via OpenCL. Uses the runner binary (fluidx3d-runner, reads config.json via F3D_CONFIG env var) if available. Falls back to the compiled case-specific binary. Supports GPU device selection by index (0 = fastest auto-detected) or by device name substring (e.g. "RTX 4090", "Arc A770"). VTK output files (velocity and density fields) are written to the execution directory for post-processing in ParaView. The runner path requires no compilation per case — build once, run any config.json. Parameters: case_name (str, required), gpu_device (str, default "0" — device index or name substring), timeout_s (int, default 3600, minimum 10). Returns: success, case_name, data.exit_code, data.output (str), data.runtime_s (float), data.vtk_files (list), data.gpu_device_used (str), data.log_file (str).

**cfd_fluidx3d_results**: Parse FluidX3D simulation results from the run log. Extracts structured data from the RESULT JSON line (final forces, completion status, MLUPS) and force history lines (STEP N F Fx Fy Fz). The RESULT line contains a complete JSON payload including success flag, case name, time steps completed, wall clock runtime, MLUPS throughput, and final forces. Parameters: case_name (str, required). Returns: success, case_name, data.forces (list of step/force dicts), data.force_count (int), data.final_forces (dict with Fx/Fy/Fz in Newtons), data.mlups (float — Million Lattice Updates Per Second), data.time_steps_completed (int), data.runtime_s (float), data.completed (bool), data.config (dict — original setup configuration).

**cfd_fluidx3d_explain**: Read the stored simulation configuration and provide a human-readable interpretation of the flow physics. Computes the Reynolds number from velocity, length, and viscosity. Classifies the flow regime (creeping/stokes if Re<1, laminar if Re<2300, transitional if Re<10000, turbulent if Re>=10000). For pipe flow, adds Darcy friction factor guidance (f=64/Re for laminar, Blasius correlation for turbulent). Includes LBM solver notes about the D3Q19 velocity set, SRT collision operator, and Smagorinsky-Lilly subgrid model for turbulence. Parameters: case_name (str, required). Returns: success, case_name, data.summary (str — full natural language description), data.Re (float), data.regime (str), data.solver_notes (str).

**cfd_fluidx3d_prebuilt**: Check for a pre-compiled FluidX3D runner binary that can skip the compilation step entirely. Checks in priority: FLUIDX3D_BINARY environment variable, case bin/ directory for fluidx3d-runner or fluidx3d_runner, and the runner build output directory (fluidx3d_runner/bin/). The runner is a standalone binary that reads config.json at runtime through the F3D_CONFIG environment variable. No parameters. Returns: success (bool), prebuilt_path (str or null — path to detected runner binary), message (str — guidance if not found).

### Model Marketplaces (3 tools)

**marketplace_search**: Search three community model repositories for CAD models. Printables uses GraphQL API with fields like title, author, downloadCount, likeCount, thumbnailURL, and modelDownloadURL. Thingiverse uses REST API (requires THINGIVERSE_API_KEY for download, search works without authentication). GrabCAD uses REST API with engineering-focused search. Parameters: source (str: "printables"/"thingiverse"/"grabcad"), query (str — search term), category (str, optional — category id from marketplace_categories), page (int, default 1). Returns: success, source (str), results (list of dicts with title, author, thumbnail, download count, like count, model URL), total (int).

**marketplace_download**: Download a model from a marketplace directly into the server's uploads directory. For Printables, fetches the first STL file from the model page. For Thingiverse, downloads the ZIP archive (which the server auto-extracts, saving all STL and STEP files inside). Parameters: source (str, required), model_id (str, required), file_url (str, required — direct download URL from search results), filename (str, required — desired filename like "model.stl" or "model.zip"). Returns: success, filename (str), size_bytes (int), extracted (list or null — list of extracted filenames for ZIP files).

**marketplace_categories**: List available search categories for a marketplace source. Each source has 15-17 categories (3D Printing, Art, Automotive, Electronics, Fashion, Gadgets, Games, Household, Kitchen, Organization, Outdoor, Pets, Sports, Tools, Toys, plus source-specific entries like Robotics or Music). Parameters: source (str, required). Returns: success, source (str), categories (list of dicts with id and label).

### Prefab UI (1 tool)

**show_marketplace_card**: Display marketplace search results as a rich interactive Prefab UI card in supporting MCP clients (Claude Desktop, Cursor). Renders up to 6 results with thumbnails, author names, download and like statistics, and direct marketplace links. Falls back to plain text in clients that don't support Prefab. Parameters: source (str), query (str), category (str, optional). Returns: ToolResult with structured_content=PrefabApp(...) in supporting clients, plain text otherwise.

## Environment Variables

FREECAD_PATH — path to FreeCAD.exe. Auto-detected from three candidate paths: D:\Dev\repos\FreeCAD\FreeCAD_1.1.1-Windows-x86_64-py311\bin\FreeCAD.exe (primary), the repo root FreeCAD.exe, and an extracted portable location in TEMP. Falls back to the primary path if none found.

FC_BRIDGE_PORT — TCP port for the FreeCAD bridge connection (default: 10946). The bridge runs inside the FreeCAD GUI process and provides access to the full OCCT geometry kernel via JSON-RPC over TCP.

FREECAD_MCP_WORK_DIR — working directory for uploads, outputs, and case files (default: %TEMP%\freecad_mcp_work). Created on startup if it doesn't exist.

PRUSA_SLICER_PATH — path to prusa-slicer-console.exe (default: a portable 2.8.1 build in the repo). Used by slice_stl for G-code generation.

FLUIDX3D_PATH — path to a cloned FluidX3D repository. Auto-detected from common locations: D:\Dev\repos\FluidX3D, ~/FluidX3D, /opt/FluidX3D. Used by cfd_fluidx3d_compile to find the LBM solver source code.

FLUIDX3D_BINARY — path to a pre-compiled FluidX3D runner binary. If set, cfd_fluidx3d_run uses this binary directly, bypassing the compilation step entirely.

THINGIVERSE_API_KEY — API key for Thingiverse REST API. Required for downloading models from Thingiverse. Key is stored in the server's settings (in-memory) and can be provided via the Settings page or the PUT /api/v1/settings endpoint.

GRABCAD_API_KEY — API key for GrabCAD engineering CAD library. Stored in the same way as the Thingiverse key.

OpenFOAM execution requires Docker Desktop for Windows and the openfoam/openfoam10-paraview56 Docker image. Run `docker pull openfoam/openfoam10-paraview56` to download the image (approximately 2 GB). The image includes all standard solvers, mesh utilities (blockMesh, checkMesh), ParaView, and MPI for parallel execution.

## REST API

The server exposes its REST API on port 10944, shared with the MCP SSE transport. All endpoints return JSON. The POST /api/v1/control/tool endpoint is the primary way to call MCP tools programmatically. Request format: {"tool": "tool_name", "arguments": {"param1": "value1"}}. Response format matches the tool's return dict. Full endpoint list: GET /api/v1/status (server health), GET /api/v1/health (detailed health with FreeCAD, Docker, FluidX3D, compiler status and uptime), POST /api/v1/upload (upload CAD files, returns filename and size), GET /api/v1/download/{name} (download processed STL/G-code/FCStd/IFC files), GET /api/v1/files (list all uploads, outputs, and G-codes), POST /api/v1/control/tool (execute any MCP tool by name), GET /api/v1/case-files/{case}/{file} (serve STL/VTK files from CFD case directories), GET/POST marketplace endpoints (search, download, categories), GET/PUT /api/v1/settings (read/write LLM configuration and marketplace API keys), POST /api/v1/chat (send a message to the Ollama CAD expert).

## Data Sources

FreeCAD geometry files: uploads/ and outputs/ directories under work_dir. CFD cases: work_dir/cfd_cases/ and work_dir/fluidx3d_cases/. Depot: work_dir/uploads/ and work_dir/outputs/ for CAD files and results. PrusaSlicer G-code: work_dir/gcode/. Logs: ring buffer in memory (2000 line, SSE stream at /api/v1/logs/stream).

## Quality Standards

All 38 tools annotated with READ_ONLY or MUTATING via @mcp.tool(annotations=...). Parameters use Annotated[str, Field(description=...)] SOTA pattern. Dual-path execution (TCP bridge then subprocess fallback) for all geometry operations. All dimensions in millimetres. All output files are served via GET /api/v1/download/{name}.
